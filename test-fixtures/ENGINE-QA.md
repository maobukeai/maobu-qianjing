The opt-in real-engine suite covers five cases across `engine-smoke.test.ts` (Chromium 155 over HTTP/SOCKS5), `engine-firefox-smoke.test.ts` (Firefox 156 over HTTP/SOCKS5), and `engine-firefox-cap-smoke.test.ts` (Firefox's effective processor cap). Normal runs skip them. They never download anything automatically or open the desktop app's profiles/database. All generated state belongs to `reports/engine-qa/run-*`.

On Windows x64, put the fixed release archive, the official GitHub release JSON (`chromium-official-release.json`) and `SHA256SUMS.txt` (`chromium-SHA256SUMS.txt`) in `reports/engine-qa`, then extract there. The test verifies the official asset digest, source archive pin, checksum manifest and executable pin before launch. The source is `https://github.com/aliasmode/aliasmode-chromium/releases/tag/v155.0.8059.85-aliasmode.5`.

The four HTTP/SOCKS5 cases each create a fresh isolated SQLite store/profile, use the production Launcher with identity gates enabled, verify real captured provenance and observable persona fields, load a local UTF-8 page through an authenticated proxy fixture, post a Chinese payload, close and relaunch the session, and verify generation-specific provenance changes. They enable the local proxy startup preference in their isolated settings file and use the production preflight on each of the three fresh launches. This checks TCP or SOCKS method negotiation only; a final launch supplies deliberately wrong fixture credentials and verifies the browser navigation is still rejected without reaching the origin. Every closed browser PID is checked for disappearance.

The proxy fixture only forwards the synthetic `maobu-engine-qa.test` hostname to its own literal `127.0.0.1` origin port. All other proxy targets are denied; global proxy settings and user credentials are never used. Chromium background networking and arbitrary hostname resolution are disabled. GeoIP lookup is disabled for this isolated test and account auto-navigation is disabled. The report records rejected background destinations rather than connecting to them. The CDP worker attaches only to the fixture's returned endpoint and does not attach to existing browsers.

Both engines must produce real 32-byte canvas/audio SHA-256 digests and preserve them across a fresh launch of the same saved identity. `MAOBU_ENGINE_QA_REALM=1` additionally records the local Firefox TypedArray/DataView diagnostic in `realm-probe.json`: it demonstrates why the production probe uses DataView for actual digest bytes and Float32 audio samples when TypedArray elements are protected by Firefox Xray wrappers. It does not disable browser protections or substitute hashes.

This proves local transport/authentication, selected persona fields, capture ownership and lifecycle. It does not certify public-IP reputation, remote DNS behavior, a real provider's reliability, or external WebRTC leak isolation. The public fixture credentials are synthetic and are used only by these local servers.

`engine-firefox-smoke.test.ts` applies the same opt-in switch to the pinned Firefox 156 Windows x64 runtime. Its release is `https://github.com/aliasmode/aliasmode-firefox/releases/tag/aliasmode-runtime-156.0.1-beta.36-r14`: save the release JSON as `firefox-official-release.json`, `SHA256SUMS` as `firefox-SHA256SUMS`, keep the original `aliasmode-156.0.1-beta.36-win.x86_64.zip`, and extract to `reports/engine-qa/firefox-156.0.1-beta.36`. It uses the production Firefox owner and checks both browser and owner PIDs disappear. Its Windows persona uses native host fonts, so no separate font pack is downloaded. Isolated startup preferences disable DNS prefetch, speculative fetches and captive-portal probes.

`engine-firefox-cap-smoke.test.ts` saves an explicit core count above this host's available parallelism, while retaining that original value in the profile and launch persona. It verifies the config actually sent to the owner worker, the owned capture and the real page all report the capped count, then checks the quality report accepts that effective launch policy. The Firefox launch and report share a read-only hardware policy; diagnostics do not generate replacement identities. Missing identity/config or invalid counts remain unknown. This case is skipped on hosts with 256 or more available cores because profile hardware permits at most 256. The current machine's tested values were saved/persona=32 and worker/capture/page=20; the previous uncapped comparison incorrectly failed this same real result. Both browser and owner shutdown are checked.

Run all five cases in PowerShell after preparing the verified local resources:

```powershell
$env:MAOBU_ENGINE_QA = "1"
bun test engine-smoke.test.ts engine-firefox-smoke.test.ts engine-firefox-cap-smoke.test.ts --timeout 180000
```
