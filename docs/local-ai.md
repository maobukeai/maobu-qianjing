# AI 工作台

工作台可以连接本机 Ollama、OpenAI 兼容 API、Anthropic 和 Gemini。服务配置属于当前工作区，发送前可以在输入框上方核对当前模型。

## 配置 API 模型服务

1. 打开「设置 → 模型服务」，点击「添加模型服务」，选择服务协议并填写连接名称和 API 基础地址。
2. 填写服务提供商发放的 API 密钥。点击「测试并加载模型」可读取模型列表，或者手动填写提供商给出的模型 ID。
3. 保存连接。可以将其设为默认模型服务，然后到「AI 工作台 → 模型设置」点击「使用默认模型」。也可以在「API 服务」里选中这条连接，点击「应用到当前对话」。

基础地址应包含提供商要求的版本前缀，如 `https://api.openai.com/v1`，填写到 `/v1` 即可。公网服务使用 HTTPS，本机回环网关可使用 HTTP 或 HTTPS。Gemini 原生接口需要 API 密钥，OpenAI 兼容服务是否需要密钥由该服务决定。Anthropic 请使用在 Claude Console 中指定了工作区的 API 密钥。未指定工作区的 Anthropic 密钥需要额外请求头。参见 [Claude API 密钥说明](https://platform.claude.com/docs/en/get-api-key)。

连接名称、地址、模型和默认项会在重启后保留。API 密钥只在当前应用运行期间保留，重启后需在已有连接中重新输入并保存。测试连接只读取模型目录。保存、设为默认和应用连接均不会提交聊天内容。

## 配置 Ollama 本地模式

如果电脑还没有 Ollama，请先按 [Ollama 官方 Windows 说明](https://docs.ollama.com/windows) 自行准备。Windows 应用通常在后台运行，默认 API 端口为 11434。本项目不会代为安装 Ollama、下载或拉取模型。

本机 Ollama 也可以转发云模型请求。需要本地模式时，在 Windows 托盘退出 Ollama，打开“编辑账户的环境变量”，为用户新建 `OLLAMA_NO_CLOUD`，值为 `1`，保存后从开始菜单重新启动 Ollama。官方也支持在 `~/.ollama/server.json` 中设置 `disable_ollama_cloud: true`；修改后都要重启。参见 [关闭 Ollama 云功能](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features) 和 [Windows 环境变量设置](https://docs.ollama.com/faq#setting-environment-variables-on-windows)。

如果使用命令行启动服务，先退出已运行的托盘服务，避免端口冲突，再在 PowerShell 中执行：

```powershell
$env:OLLAMA_NO_CLOUD = "1"
$env:OLLAMA_HOST = "127.0.0.1:11434"
ollama serve
```

以上变量只影响当前 PowerShell 及其启动的服务；托盘应用应使用前述用户环境变量并重启。`ollama serve` 是官方服务启动命令；默认监听本机回环地址。参见 [官方 CLI](https://docs.ollama.com/cli) 和 [服务配置说明](https://docs.ollama.com/faq#how-do-i-configure-ollama-server)。

可用以下只读命令确认已有模型和接口。它们不下载模型、不生成回答：

```powershell
ollama ls
Invoke-RestMethod -Uri http://127.0.0.1:11434/api/tags
```

命令和返回格式见 [官方模型列表命令](https://docs.ollama.com/cli#list-models) 与 [GET /api/tags](https://docs.ollama.com/api/tags)。模型列表为空时，需要先自行准备符合电脑资源条件的本地模型；本应用不自动选择或下载模型。

## 在工作台使用

1. 打开「AI 工作台 → 模型设置 → 本地 Ollama」，填写 Ollama 根地址，默认 `http://127.0.0.1:11434`。
2. 点击连接，选择服务中已有的本地模型。
3. 输入问题，点击发送或按 `Ctrl / ⌘ + Enter`。可让模型解释问题、拟定步骤、草拟脚本；回答不会自动修改环境、执行代码或调用 MCP。
4. 生成过程中可取消；应用中止请求并恢复草稿。若显示无法确认取消，请检查本地服务状态后再试。

地址只接受 `http://` 或 `https://` 的 `127.0.0.1`、`localhost` 或 `[::1]`，可指定端口；不能带账号密码、查询参数、片段或 `/api` 等子路径。HTTPS 需要有效、可信的证书。应用在后端请求本机 API，无需为工作台放开浏览器跨域访问。

Ollama 本地 API 无需密钥。工作台排除常见云模型名称及带远端来源元数据的模型，每次聊天前重新核对模型列表。Ollama 的云功能由其服务配置控制。参见 [官方 API 的本地与云服务区别](https://docs.ollama.com/api/introduction)。

工作台旁的 MCP 接入入口供外部 MCP 客户端配置连接。当前目录含 12 项本地工具，其中 `aliasmode_fingerprint_review` 只读所指定环境的保存配置与指纹报告，不开启浏览器、不采样、不验证进程存活；`aliasmode_network_discover` 只检查受限的回环端口和 SOCKS5 方法，不发送凭据、连接外部网站或修改设置。返回数据排除凭据、原始样本、控制端点和私有来源摘要。本工作台的聊天不会自动调用这些工具。

网络设置中的“本机代理启动前检查”默认关闭，开启后只作用于浏览器环境的新启动，不替代 Ollama 连接检查。指纹设置页支持中英质量说明、安全的配置/观察值对照及关注项筛选，MCP 的离线报告可供人工或外部客户端规划后续检查。

Ollama 文档等界面外链使用受限的 HTTPS 原生命令；目前验证包括 Chrome 模拟桥接调用和 Rust 目标规则，尚未实际启动系统浏览器验收。设置切换页签时会回到内容顶部。

## 对话与匿名上下文

默认发给所选模型服务的内容为问题、近期对话和固定的助手能力说明。切换连接后，旧消息仍可在当前页面查看，发送上下文从这次切换重新开始，匿名工作区概览也会恢复为关闭。工作台可以提供问答、计划和代码草稿。

“包含匿名工作区概览”默认关闭。开启后增加环境总数、运行数、浏览器引擎分布、已配置代理数量、分组数量，以及 `Group 1` 等匿名分组的环境计数。不会追加环境 ID、名称、真实分组名、页面内容、账户密码、Cookie、2FA、代理凭据、保存会话或私有浏览器控制地址。用户自己输入的文字会按原意发送，因此不要主动粘贴秘密。

对话只保留在本次界面会话内，重启后清除，应用不写入聊天数据库或文件。界面最多保留 40 条消息；发送时保留近期完整问答，在长度预算内选取至多 23 条消息。过长的历史回答以带标记的截取片段进入上下文，界面显示的回答保持完整，并提示上下文已缩短。“新对话”可在发送下一条消息前撤销。Ollama 自身的日志及数据管理由用户另行控制。

在「设置 → 指纹质量」选择环境后，可以点击「生成 AI 说明草稿」。工作台先提供可展开的匿名摘要，最多列出 12 个需关注项。摘要只使用固定检查类别、状态和计数，不读取实际配置、环境名称、ID 或原始观测。点击「追加到草稿」会保留原有消息；超出 8 KiB 时保留原稿，供缩短后重试。整个过程无需连接模型，随后可自行编辑并手动发送。

| 限制 | 当前值 |
| --- | --- |
| 输入 | 服务最多 24 条消息，单条 8 KiB UTF-8，总计 48 KiB；界面发送至多 23 条 |
| 回答 | 文本最多 64 KiB；每次请求最多生成 2048 token，本机 Ollama 上下文窗口设为 8192 token |
| 传输 | JSON 请求最多 128 KiB，聊天响应最多 256 KiB，模型目录最多 256 项 |
| 时限与并发 | Ollama 模型列表 5 秒，API 模型列表 10 秒，聊天整体 120 秒。工作台一次生成一条回答 |

这些是应用限制；实际输出还取决于本地模型能力和电脑资源。请求失败会显示结构化错误，不替换为模拟回答。

## 常见问题

| 提示或现象 | 排查方式 |
| --- | --- |
| 服务不可用 | 确认 Ollama 已启动，先检查 `/api/tags`；核对端口和地址。改变用户环境变量后需重启 Ollama。 |
| 地址无效 | Ollama 使用本机回环根地址。API 服务请核对基础地址、协议和版本前缀。 |
| API 密钥被拒绝 | 在「模型服务」检查密钥是否已配置、是否有模型访问权限。重启后需要重新输入密钥。 |
| 没有可选模型 | 使用 `ollama ls` 核对已准备的本地模型；云模型和远端模型会被排除。 |
| 请求超时 | 缩短对话，或选用电脑能够运行的较小本地模型；应用不代为拉取模型。 |
| 端口被占用 | 核对已有 Ollama 托盘服务；不要再启动第二个监听相同端口的服务。 |
| 无法确认取消 | 工作台已经停止等待并保留草稿；检查本地服务是否仍在处理，再重新发送。 |

自动化测试使用隔离服务验证模型请求、错误、取消和上下文范围，响应由测试夹具生成。真实模型的推理速度、模型权限和额度由用户连接的服务决定。
